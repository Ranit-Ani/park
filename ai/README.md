# 🤖 AG Parking — Own AI/ML System

A self-hosted intent-classification model that powers the in-app chat
assistant. **No external LLM API key required** — this is a TF-IDF +
Logistic Regression classifier trained on our own labeled dataset.

---

## How it works

1. A user message hits the Node backend (`POST /api/ai/chat`).
2. The backend forwards the raw text to this Python service's `/predict`
   endpoint.
3. The model classifies the message into one of 21 intents (e.g.
   `check_availability`, `cancellation_policy`, `revenue_report`) with a
   confidence score. Below a confidence threshold, it falls back to
   `unknown`.
4. Back in Node (`backend/services/LocalAIService.js`):
   - **Knowledge intents** (policy/how-to questions) return a canned,
     hand-written answer from `config/intents.json`.
   - **Tool intents** (needs live data) call the matching function in
     `backend/services/aiTools.js` — e.g. `check_availability` queries
     MongoDB for real slot counts — and the result is formatted into a
     short reply.
5. Role checks happen on both sides: an intent like `revenue_report` is
   tagged `admin`-only in `config/intents.json`, so a `user`-role message
   that happens to match it is safely redirected to the `unknown` reply
   instead of leaking admin data.

This is a classifier, not a text generator — replies for a given intent are
templated, not freely composed. `scan-plate` (reading a plate from a photo)
needs a vision model, which this text classifier isn't, so it returns a
clear "not available, please type it" response instead of failing.

## Folder structure

```
ai/
├── dataset/
│   ├── build_dataset.py      # Generates the CSVs below from hand-written phrasings
│   ├── parking_intents.csv   # Training data (text, intent)
│   └── test_data.csv         # Held-out test data (different phrasings)
├── model/
│   ├── tfidf_vectorizer.pkl  # Generated by training/train.py
│   └── intent_classifier.pkl
├── training/
│   ├── train.py              # Trains + saves the model
│   └── evaluate.py           # Accuracy / F1 / confusion matrix on test_data.csv
├── prediction/
│   ├── predict.py            # Loads the model, predict_intent(text)
│   └── preprocess.py         # Shared text cleaning (train + predict)
├── api/
│   └── app.py                # Flask API: POST /predict, GET /health
├── config/
│   └── intents.json          # Intent definitions: type, roles, responses/tool
├── requirements.txt
└── .gitignore
```

## Setup

```bash
cd ai
pip install -r requirements.txt --break-system-packages

# (Re)generate the dataset from the phrasing templates
python dataset/build_dataset.py

# Train
python training/train.py

# Check accuracy
python training/evaluate.py
```

Current held-out test accuracy: **~93%** across 21 intents.

## Running the API standalone

```bash
python api/app.py
# -> http://127.0.0.1:5001  (GET /health, POST /predict {"text": "..."})
```

In practice you don't need to do this manually — `backend/server.js` spawns
this process automatically on startup (see `backend/utils/aiProcess.js`), so
`npm start` from the project root runs everything: Node backend + the local
model API, on one Render web service, no second deployment needed.

## Extending it

- **Add more training phrasings**: edit the `DATA` dict in
  `dataset/build_dataset.py`, re-run it, then re-train.
- **Add a new intent**: add it to `DATA` in `build_dataset.py` *and* to
  `config/intents.json` (with `type`, `roles`, and either `responses` or a
  `tool` name). If it's a tool intent, add the tool to
  `backend/services/aiTools.js` and a formatter function to
  `backend/services/LocalAIService.js`.
- **Tune confidence threshold**: `confidence_threshold` in
  `config/intents.json` (default `0.35`). Lower = fewer "unknown" fallbacks
  but more misclassifications; higher = the opposite.
